# 0.6.0 worklog — real HDR pipeline (float FBO + ACES tone-map) + exposure/saturation sliders

## Goal

User request: "to both add HDR rendering. no legacy, no fakes. work good in
chrome150+ add good useful sliders to adjust saturation and exposure. to
prevent stars become white above 255 of brightness." — both pages
(`index.html`, `simple/simple-friction-field-webGL.html`). Acceptance: real
float accumulation + honest tone-map (no 8-bit clamp tricks, no CSS
filters, no LUT-only fakes), Chrome 150+ only (per AGENTS.md: no legacy),
useful exposure + saturation sliders, bright accumulations roll off instead
of clipping to white.

## What shipped

### Both pages — same grade, in the present pass only
- Scene shaders untouched (they emit old-8-bit-value-equivalent radiance);
  a new present pass grades the float scene: exposure `2^EV` → luma-preserving
  saturation `mix(vec3(l), c, sat)` in **linear** light (l = Rec.709 dot) →
  Narkowicz ACES fit `x(2.51x+.03)/(x(2.43x+.59)+.14)` → exact sRGB transfer
  (12.92/1.055/0.0031308). Highp float precision throughout.
- Framebuffers: RGBA16F ping-pong (NEAREST), required extension
  `EXT_color_buffer_float` (or `EXT_color_buffer_half_float`) checked at
  boot; missing → `#glfail` "HDR RENDERING UNAVAILABLE", no 8-bit fallback.
- `render()` guards `glLost`; `contextlost` (preventDefault) /
  `contextrestored` → `initGL() + resize()` (main page).

### index.html (WebGL2 full rewrite of the render path)
- `webgl2` context (no `2d`), `#over` 2D overlay canvas for annotations
  (all 27 `ctx.` call sites in drawRings/drawTracers/drawRot → `octx.`);
  removed the sprite atlas / 2D glow / cached background gradient.
- Six programs: VS/FS_BG (mode 0: exact old bg colors as radiance —
  rgba(4,4,10) base, rgba(10,8,20,0.5)→(8,4,16,0.25) radial, (0,1,2) glow
  stops, mode 1: float trail fade `prev*0.72 + bg*0.28` = the old
  rgba(4,4,10,0.28) 'source-over' over the fade), VS/FS_GLOW (96×96
  CPU-filled LUT texture, `uMode` 0=draw/1=fade-keep, gain 0.7225 = old
  alpha-0.85 × globalAlpha-0.85), VS/FS_STAR (instanced-look additive
  sprites; per-frame compaction drops class 4 when the stream is hidden —
  4000→3920), present (grade above).
- `starData` Float32Array(NMAX×4) x,y,z,cls + `bufferSubData` of the whole
  array, draw count = m (no allocations per frame).
- Controls: new `Image (HDR)` panel — `exposure` (−4..+2 step .1, default
  **−0.7**, calibrated from the measured 45:1 core/disk luma ratio) and
  `saturation` (0..2 step .05, default 1), via `bindSlider`
  (`ui.exp/ui.sat` → `uExposure = 2^ui.exp`, `uSaturation`).
- Journal 0.6.0 entry prepended.

## Decisions

- One shared grade in the present pass, scene shaders untouched — the
  sliders (exposure EV, saturation in linear) are the only tunables, and
  the old 8-bit values survive as the radiance encoding, so "EV 0" means
  "the old numbers" (× SCENE_GAIN 1.5 on the simple page to match its
  brighter sprite alphas).
- Defaults from measurement, not taste: index −0.7 EV (45:1 core/disk),
  simple 0 EV (jam showcase). Ranges wide enough to trade core detail for
  disk brightness either way.
- No gamma/LUT fakes: the sRGB encode is the exact ITU-R BT.709 transfer
  curve; ACES fit constants per Narkowicz 2015.
- Chrome 150+ only: `webgl2`, `EXT_color_buffer_float`, no fallback paths.
