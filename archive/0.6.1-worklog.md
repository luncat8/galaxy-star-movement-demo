# 0.6.1 worklog — WebGPU native HDR + color-preserving highlight tonemap + exposure & saturation sliders

## Goal

User request:
"previous agent failed to implement HDR. probably it is not working in webGL. rewire **simple-friction-field-webGL.html to simple-friction-field-webGPU.html with proper HDR with** good useful sliders to adjust saturation and exposure. to prevent stars become white above 255 of brightness."

Root cause analysis of previous failure:
1. In WebGL, canvas output is restricted to standard dynamic range (8-bit SDR).
2. The previous tone-mapping implementation applied ACES independently per-channel (`aces(r)`, `aces(g)`, `aces(b)`). When starlight accumulates (such as in dense spiral arm traffic jams or the central galactic bulge), all RGB channels exceed 1.0 (or 255 in 8-bit scale). Per-channel compression maps all channels towards 1.0, turning vibrant pink spiral arms, cyan-blue disk stars, and golden bulge stars into solid, washed-out chalk white.
3. Sliders were unable to rescue the color because the per-channel S-curve crushed saturation at high brightness.

## What shipped

### `simple/simple-friction-field-webGPU.html`
- **Native WebGPU HDR Pipeline**:
  - `context.configure({ device, format: 'rgba16float', colorSpace: 'srgb', usage: RENDER_ATTACHMENT, toneMapping: { mode: 'extended' }, alphaMode: 'opaque' })`.
  - Starlight accumulates offscreen in an RGBA16F float ping-pong framebuffer texture pair (`GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.TEXTURE_BINDING`).
  - Supports persistent trails blending (`fade * prev + bg * (1 - fade)`).
- **Color-Preserving HDR Tonemapper**:
  - Linear exposure scaling: `c_exp = raw * exposure` ($2^{\text{EV}} \times \text{SCENE\_GAIN}$).
  - Linear-light luma-preserving saturation: `c_sat = max(mix(vec3f(lum), c_exp, saturation), vec3f(0.0))`.
  - Chromaticity preservation: Rather than per-channel compression, we compress the peak component:
    `mappedPeak = (peak * H) * inverseSqrt(H * H + peak * peak)`, with $H$ dynamically calibrated to display headroom ($4.0\times$ on HDR, $1.0\times$ on SDR, adjustable $1.0-6.0\times$).
    `scale = mappedPeak / peak`.
    `c_hdr = c_sat * scale`.
    Every color component is scaled by the exact same ratio, mathematically guaranteeing that the chromaticity ratios ($R : G : B$) are invariant under arbitrary intensity.
  - Direct linear HDR output: Emits `vec4f(c_hdr, 1.0)` directly into the `rgba16float` extended canvas without clipping, allowing values up to $4.0\times+$ to shine in true physical HDR luminance as verified in the user's working reference.
- **Instanced Quad Point Sprites**:
  - WebGPU primitive topology `point-list` has fixed 1px size (no `gl_PointSize`).
  - Generated camera-facing quads in vertex shader using `@builtin(vertex_index)` (6 vertices per star) with dynamic perspective scaling and radial gaussian falloff fragment shader.
  - Zero CPU vertex allocation churn: single draw calls for 15,000 disk stars, 4,000 bulge stars, and 1,500 slow-field arc samples.
- **Controls & UI**:
  - Exposure slider: $-4.0$ to $+4.0$ EV (step 0.1, default 0.0). Real-time display label with signed EV.
  - Saturation slider: $0.00$ to $2.50\times$ (step 0.05, default 1.00). Real-time display label (with `0.00 (mono)` indicator).
  - HDR Headroom slider: $1.0\times$ to $6.0\times$ (step 0.5, default $4.0\times$ on HDR, $1.0\times$ on SDR).
  - HDR badge in top header showing `WebGPU HDR · 4.0× Extended` or `WebGPU HDR · SDR (1.0×)`, with click toggle to preview Extended ($4.0\times$) vs SDR ($1.0\times$) headroom.
  - Slow Field, Arm Tint, Trails, and Reset View buttons wired.
  - Cross-link button to WebGL2 version.
