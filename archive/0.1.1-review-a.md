The key distinction is **visual stability** versus **physical stability**.

The linked animation is an excellent *density-wave illustration*, but not a self-gravitating N-body benchmark. Its renderer deliberately uses radius-dependent, slightly rotated elliptical orbits to create permanent arms, then hides point noise with nebulae and H-II regions. Its own documentation notes that real stellar paths are rosettes rather than those closed ellipses, and that even ~60k naked points still look disconnected without a diffuse rendering layer: [renderer explanation](https://beltoforion.de/en/spiral_galaxy_renderer/).

Our current demo is more dynamically honest: collisionless persistent stars in a smooth potential, a symplectic integrator, ramped bar/spiral modes, and no friction. That necessarily makes “perfect, permanent, full-disk” arms harder.

## Things I would **not** do

- **Do not add drag/friction to stars.** It removes angular momentum and eventually collapses/piles particles into the centre. Drag is appropriate for gas, not collisionless stellar orbits.
- **Do not just increase spiral amplitude.** It can improve contrast briefly, but it drives resonances harder, heats or traps stars, and makes the outer disk less orderly.
- **Do not use independent bar and spiral pattern speeds as the default.** Their beat pattern makes the response visibly pulse and wash out. They are useful as an “experiment” mode, not as the stable presentation.

## Best short-term solution: improve the presentation without falsifying the dynamics

### 1. Slow and interpolate the visible motion
The default display advances roughly `0.1` simulation units per rendered frame. At the current screen scale, stars can move several pixels frame-to-frame, which reads as jitter/noise even if the orbit is numerically fine.

Use:

- default visual speed around `0.02–0.03`;
- keep physics substeps at `dt = 0.01`;
- store previous positions and interpolate at render time.

This improves perceived smoothness without changing the orbit or conservation behavior.

### 2. Add a density / surface-brightness layer
Keep every star as a persistent simulated object, but do **not** require the viewer to infer a galaxy from only 4k bright points.

Render two layers:

1. **Resolved stars** — the existing moving particle sprites and tracers.
2. **Diffuse density light** — bin thin/young disk stars into a low-resolution map, blur it, and draw it softly beneath the point stars.

The density layer should be explicitly labeled as a *surface-brightness estimator*, not another force or fake particle system. It represents the unresolved stars a telescope would blend into a luminous disk. This is the main reason the reference looks calm rather than granular.

A very effective version is to draw only the **non-axisymmetric density excess** in the diffuse layer, so smooth disk light stays subtle while bar and arms become visible.

### 3. Weight what observers would actually see
The old thick disk, bulge, and halo are physically valuable but visually dilute the arm signal.

For the default presentation:

- keep halo/bulge faint;
- make the young, cold disk the primary blue-white arm tracer;
- use a subdued warm unresolved disk underneath;
- optionally add deterministic, short-lived H-II/emission knots around arm overdensities.

That matches the real observational fact that spiral arms are especially prominent in gas, dust, and young luminous stars—not because all old stars remain permanently inside an arm.

### 4. Offer a protected “stable density-wave” preset
The current stable region is already close to the right one:

- bar and spiral share one pattern speed;
- patterns are adiabatically ramped in;
- no drag;
- moderate bar/spiral amplitudes.

Make that a named preset and visually separate it from an **experimental** mode. If the user detunes `Ωbar` and `Ωspiral`, show a small warning such as: “Independent pattern speeds: beating and arm wash-out are expected.”

That prevents an intentionally unstable exploratory configuration from being mistaken for a simulation fault.

## Better physical initial conditions

The current disk is a reasonable fast approximation, but sampled Gaussian velocity dispersions are not an exact steady distribution function of the axisymmetric potential. A more rigorous improvement is:

- sample a **quasi-isothermal/action-based distribution function** for the disk;
- grow the bar/spiral adiabatically;
- retain the present leapfrog integrator and diagnostics.

This reduces initial ringing and reduces the need for a long visual settling period. It will improve the baseline, but it will **not** magically give permanent crisp arms beyond corotation: that is a limitation of a rigid test-particle wave, not only of the initial conditions.

## If the goal is to match the reference exactly

Add a separate, honestly labeled **“kinematic density-wave mode.”**

It would use the reference-style construction:

- orbit eccentricity varies with radius;
- periapsis angle twists smoothly with radius;
- stars move differentially around those precomputed orbit families;
- a bar-like inner region and spiral-like outer orientation are built into the orbit atlas;
- diffuse nebula/H-II layers provide the arm brightness.

This mode will look exceptionally clean forever and retain persistent star identities. But it should not claim resonant capture, angular-momentum exchange, or self-consistent stellar dynamics.

## If the goal is more astrophysical realism

The long-term route is not direct N-body gravity; it is a **2D particle–mesh disk solver**:

- deposit disk mass to a polar or Cartesian grid;
- solve Poisson’s equation on the grid;
- interpolate forces back to particles;
- use softening and a live halo/background;
- later add a dissipative gas layer plus star formation/feedback.

That can produce transient and recurrent arms through swing amplification. However, it brings an important truth: a realistic collisionless disk does **not** promise eternal clean arms. Long-lived bright arms generally need gas physics and continual formation of young luminous stars.

## Recommendation

I would make the next version a **hybrid presentation upgrade**, not a new gravity engine:

1. reduce default visual speed and add render interpolation;
2. add a soft unresolved density-light layer from the existing persistent particles;
3. keep young stars visually dominant in arms;
4. add a locked stable preset and move detuned pattern speeds into an explicit experiment mode;
5. only then consider a separate kinematic-reference mode or a full particle-mesh project.

This gives a much quieter, reference-like galaxy while preserving the current model’s important strengths: persistent stars, stable Hamiltonian dynamics, real streaming through density-wave crests, and no artificial central collapse.
