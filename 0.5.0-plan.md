# 0.5.0 plan — global m=2 self-gravity as a separate engine variant (galaxy.js untouched)

Goal: replace the local WKB estimate of the disk's own gravity with a GLOBAL
m=2 Green's-function solve, and answer the question 0.4.0/0.4.1 left open — can
the disk's own gravity hold spiral arms beyond corotation past the settle
transient? The new physics ships as a SEPARATE ENGINE FILE selected from the
page, so the kinematic + WKB path stays the shipping default and stays
byte-identical.

## 1. Where the variant lives (separate engine, not a separate page)

Requirement: keep the old math, add another variant, no build, no modules,
no vendored FFT library, no duplicated code.

| option | verdict |
|---|---|
| a) a solver branch inside `galaxy.js` | rejected — edits the one validated engine; "the old math is unchanged" becomes an argument instead of a fact, and two theories share one hot loop |
| b) separate page `selfgravity.html` + its own engine | rejected — duplicates ~500 lines of renderer/UI/controls (AGENTS.md: avoid duplication), the two pages drift, and the A/B that has to be judged by eye (finding 20) leaves the page |
| c) separate engine `selfgrav.js` + an engine switch in `index.html` | **chosen** |

The enabler for (c) is that `P.live.freeze` already exists: `computeAccel`
refreshes the force tables only when `!P.live.freeze`, and otherwise just
samples `st.live.amp/th` for the force. So an external engine can own the table
refresh with ZERO edits to `galaxy.js`:

- `P.live.freeze = true` → `galaxy.js` stops calling `updateLive`; the per-bin
  m=2 moment (`cr/ci/ms`) still accumulates in the hot loop and nothing clears
  it, so the variant reads and clears it.
- the variant calls the exported `Galaxy.updateLive(st,P,t,dt,gain)` itself to
  get measurement + pattern-frame rotation + radial smoothing + tau low-pass +
  the completeness/edge mask (steps 1-2 of 0.4.0), then overwrites `amp/th`
  with the global solve. No measurement code is duplicated.
- the force, the Catmull-Rom table interpolation, the `potential()`/
  `accelSingle()` diagnostics and `check-gradient`/`check-jacobi` are reused
  verbatim — the global term enters through the same `amp(R), theta(R)`
  interface the WKB term used. 0.4.0's claim ("a global solver replaces this
  one line and nothing else") is structurally true, not just intended.

Cost of the seam: the force table lags by `refresh` substeps instead of 1. That
is a knob, not a defect — a longer interval averages more shot noise per solve.

Traps at this seam (all bite silently):
- `cr/ci/ms` are SUMS over the substeps since the last refresh, not means. The
  variant must divide them by the ACTUAL substep count accumulated since its
  last refresh (the nominal `refresh` in the advance loop, but settle hands it
  chunk-sized counts) before `updateLive`, or the self-term grows with the
  window length and the completeness mask saturates; the `dt` passed to
  `updateLive` is the same window's elapsed time, so the tau low-pass keeps a
  constant time constant.
- `updateLive` unwraps `theta` (its step 4) before returning; after overwriting
  `theta` the variant must unwrap again, or `dtheta/dR` jumps by 2*pi and the
  force's wavenumber term spikes (finding 1).
- the force reads `amp/th` directly — `gain` is baked into the table at write
  time, not multiplied at evaluation. So the table must be re-written while
  `P.live.g` fades (page keeps ticking with the fading gain until it reaches
  0), or switching the solver off cuts the force instead of fading it
  (finding 1 again).
- the solved `amp` must be tapered by the same `LIVE_EDGE` factor the grid
  uses: the force hard-cuts at `R < LIVE_RHI` (galaxy.js, untouched), and the
  WKB path only stayed smooth because its `mask` on the OUTPUT carried that
  taper. The global term masks its INPUT (completeness x edge); it multiplies
  its OUTPUT by the edge taper alone so the field reaches zero before the cut.
- the INNER boundary is the sharp one: `liveSample` clamps `amp` to 0 for
  `R < LIVE_RLO` with the derivative zeroed, so the table arriving at that
  boundary must have value AND Catmull-Rom slope = 0 — which pins the first
  TWO bins to exact zero (slope at the boundary is ~0.5*amp[1]/dr). The
  WKB tables squeak by on their small inner amplitude (frozen p99 1.5e-3);
  the global solve's inner field is ~5x stronger and does not: measured
  frozen-table Jacobi p99 6.5e-3, dt-invariant (a crossing kink, not
  truncation), fixed to 2.8e-4 by zeroing bins 0-1 (edge factor
  `sstep((rc-0.75)/0.15)`, lost zone R<0.78 = inside the ILR, outside the
  study). Gate this in check-jacobi's frozen-variant run.

Page wiring (all in `index.html`, zero `galaxy.js`): after every
`Galaxy.step` in `advance()` and after every settle chunk (chunk =
`refresh` substeps while the variant is armed) the page ticks
`SelfGrav.step(st, P, t, dt, n, gain)` with `gain = Galaxy.liveGain(...)`.
The tick counts substeps and, every `refresh`, runs the refresh above.
`P.sg` is attached at runtime by `SelfGrav.ensure(P)` — `defaultParams()`
is never edited.

New file `selfgrav.js` (classic script tag after `galaxy.js`, `module.exports`
guarded), exporting `SelfGrav`. `index.html` gains a 3-way select and no
physics. `galaxy.js` gains nothing: gate `git diff --quiet -- galaxy.js`.

## 2. Pre-flight (measured — `experiments/measure-selfgrav-kernel.js`)

Calm preset (Om 0.30, As 0.06, bar off), N=20k, shipping ICs, pattern-frame
phasors averaged over T=30-70 (21 samples, 2 tu apart), 32-bin grid. Logs in
`experiments/logs/selfgrav-preflight-eps{0.08,0.15,0.30}.txt`.

- Toomre `Q = kappa sigR / (3.36 G Sig0)` of the sampled disk: **min 2.71 at
  R=1.38**, 6.04 at R=3.07 (spiral CR 3.02), 8-32 beyond R=4. The disk is far
  from self-gravitating-unstable, so a gain-1 loop will not go bar-unstable at
  these dispersions; the flip side is that the outer disk is very stable and
  may simply not respond. sigR measures 0.20-0.39 (class mix + epicyclic
  streaming), not the 0.05-0.15 input dispersions.
- Global solve vs the shipped WKB estimate, same measured Sig2, same run:
  inside CR the global term is 2.2-9.4x the WKB one (3-5x over most of the
  arm zone); beyond R=4 it is **6-160x, peaking at 112-161x across OLR**,
  because the kernel is non-local — the outer potential is fed by the strong
  inner response instead of by the local moment, which collapses across OLR
  (finding 25).

  | R | Sig2 | WKB 2*pi*G*Sig2/k | global m=2 | ratio | global / As |
  |---|---|---|---|---|---|
  | 1.38 | 7.9e-3 | 9.2e-3 | 3.43e-2 | 3.7 | 0.57 |
  | 2.35 | 3.8e-3 | 7.5e-3 | 3.38e-2 | 4.5 | 0.56 |
  | 3.07 (CR) | 1.8e-3 | 4.6e-3 | 2.35e-2 | 5.1 | 0.39 |
  | 4.03 | 3.2e-4 | 1.1e-3 | 1.05e-2 | 9.6 | 0.17 |
  | 4.51 | 1.6e-5 | 6.2e-5 | 7.01e-3 | 112 | 0.12 |
  | 4.75 (OLR) | 9.3e-6 | 3.7e-5 | 5.94e-3 | 161 | 0.10 |

  At R=4.5 the WKB loop had 6.2e-5 to work with (0.1% of the imposed spiral
  field As=0.06); the global kernel has 7.0e-3 (12%). That is the whole reason
  to build it — and it is an OPEN-loop number, so it is an upper bound on what
  the closed loop can do.
- Softening: eps=0.15 (between thin b=0.10 and thick b=0.30). At R>=4 the solve
  is softening-independent (7.05e-3 / 7.01e-3 / 6.85e-3 for eps 0.08/0.15/0.30,
  3%); inside R=1.4 it spans 1.5x (3.93e-2 -> 2.61e-2). eps is an inner-
  amplitude knob only, so the outer-disk answer cannot be an eps artifact.
- Kernel discretization: 32 bins, source radius integrated over the bin
  (NSUB=8), 256-point azimuthal quadrature → max relative error **1.86e-3** vs
  an 800x2048 dense quadrature over the same R range, eps-independent. The
  m=2 radial wavelength is 1.68 at R=2 and 4.21 at R=5 against a 0.241 bin, so
  the grid resolves the wave with 7 and 17 bins.
- Measured trap worth keeping: comparing the kernel against a quadrature that
  integrates R' from 0 reports a fake 5.6% error — the grid starts at
  `LIVE_RLO = 0.3` and the mass inside it is real. That hole is why m=0 stays
  out of the solve (section 3.3).

## 3. Physics

### 3.1 Kernel

Plummer-softened razor-thin layer, exact m-harmonic, precomputed once:

    g_m(R,R') = int_0^2pi cos(m psi) / sqrt(R^2 + R'^2 - 2 R R' cos psi + eps^2) dpsi
    K_m[i][j] = -G * int_{bin j} R' g_m(R_i,R') dR'          (NSUB=8 sub-points)
    Phi_m(R_i) = sum_j K_m[i][j] * (harmonic amplitude of Sigma at R_j)

32x32 for m=2, built at setup: measured 68 ms (2.1M sqrt). A solve is one
32x32 matrix-vector product per refresh: measured 0.03 ms, i.e. three orders of
magnitude below the per-star loop.

Harmonic convention: `Sigma = Sig0 + a_1 cos(phi) + b_1 sin(phi) + a_2 cos(2phi)
+ b_2 sin(2phi)`, so the harmonic amplitude is `a_m = 2 |phasor| / area` — TWICE
the `|phasor|/area` that the shipped WKB `est` uses. Any A/B against the WKB
column must state that factor or it will read as a 2x win.

### 3.2 Phase and sign

The pattern-frame phasor from `updateLive` has the density crest at
`u = arg(pr + i pi)`, with `u = 2(phi - Om t - p L(R))`. The kernel maps the
masked density harmonic `a = mask * 2 * (pr + i pi) / area` to `Phi = K * a`.
`K` is real and negative, so for a crest-phase input the solved potential is
`-|Phi| cos(u - arg(pr+i pi))`: a WELL at the density crest (the solve itself
already carries the +pi: `arg(K*a) = arg(a) + pi`). The force path wants
`amp cos(u - theta)`, i.e. a hill at `theta`; matching the two gives

    est = gain * |Phi_i|,  amp[i] = cap*est/(est+cap) * edge(i),
    theta[i] = atan2(Phi_i_im, Phi_i_re)          /* NO extra +pi */

The shipped WKB rule is `theta = atan2(pi, pr) + pi` on the DENSITY phasor;
the kernel product replaces both the amplitude AND that +pi — `arg(K*a)` is
already `arg(a) + pi`, so adding the shipped offset again double-counts and
puts the well on the HILL (finding 22's bug rebuilt from algebra). The sign
claim is never trusted from algebra alone: section 5's `check-selfgrav-phase.js`
measures the well against an independently measured crest and gates +-10 deg.
The mask moves too: the WKB term masked its OUTPUT, the global term masks its
INPUT (an empty outer bin must not inject noise into the solve at every
radius); the OUTPUT keeps only the edge taper (section 1). `theta` must be
re-unwrapped after the overwrite (section 1).

### 3.3 Which harmonics

- m=2 only. m=1 solves to a 6.8e-4 peak against m=2's 3.4e-2 — 50x below,
  and its density moment (3.6e-4 peak) is 25x below m=2's (8.9e-3).
- m=0 excluded, deliberately: the static potential already carries the disk's
  own mass (thin 0.50 + thick 0.30 of the total), so an axisymmetric self-term
  double-counts it and moves the rotation curve; and the grid's R<0.3 hole
  biases exactly that term (section 2). A contrast solve on
  `Sig_meas - Sig_model` is 0.6.0 material.

### 3.4 Parameters

    P.sg = { solver: 0, eps: 0.15, nsub: 8, nq: 256, refresh: 4, cap: 0.10 }
    /* solver 0 = WKB (0.4.x, default), 1 = global */

`P.sg` is attached at runtime by `SelfGrav.ensure(P)` (page init, first study
step) — `defaultParams()` gains no key, `galaxy.js` stays byte-identical.
`P.sg.solver` is the engine switch (render/study scripts read it); the page's
select is the UI mirror of it.

`P.live.gfb` stays the single master gain for both solvers (it already rides
`spiral.g`, fades with `(1 - bar.g)` per finding 11, and the page's slider and
`m` key already drive it — index.html:846,907), so the page gains one select
and no new gain. Gain enters before the saturation, exactly as in the WKB
line: `est = gain * |Phi|`, `amp = cap*est/(est+cap)`. `P.live.cap` is
switched with the solver: 0.02 for WKB, 0.10 for global — the global
amplitude is physical, not a gain-scaled estimate, and the soft saturation
`C*Phi/(Phi+C)` at the measured inner amplitude Phi=3.4e-2 passes 37% at the
0.4.0 cap C=0.02, 59% at 0.05 and 75% at 0.10 — the old cap would attenuate
the very term the study measures. The saturation stays as the runaway brake.

## 4. Study (three steps, each with its own gate)

1. **Audits before any closed loop** (the 0.4.2 hand-off requires this):
   `check-poisson.js` for the kernel, `check-selfgrav-phase.js` for the sign —
   scan phi of static + variant-table potential at R=1.5/2.5/3.5/4.5 and print
   hill/well offsets from an independently measured density crest
   (check-arm-phase part A applied to the new term). No closed-loop run before
   both pass.
2. **Open loop** (`experiments/check-selfgrav-open.js`) — the decisive
   experiment. Drive the force from a table measured with the force zeroed and
   then FROZEN (no feedback): prime the normal measurement pipeline at gain 0
   (the table stays 0 -> no force; `pr/pi` and the mask converge normally),
   average the raw solved `Phi` over T=30-70, write `amp/th` once from the mean
   with the drive gain, stop ticking. The force path reads `amp/th` directly,
   so the frozen table drives at full strength with zero feedback. If the
   non-local field alone organizes R>4, the kernel is the answer; if it does
   not, the disk is unresponsive at Q=8-32 and no closed loop can help.
   Without this step a closed-loop null result cannot be attributed to
   anything.
3. **Closed loop** (`experiments/check-selfgrav-loop.js`), gain ladder
   g = 0.1 / 0.25 / 0.5 / 1.0 plus the g=0 twin, calm preset,
   N=10k and 40k (finding 5), sampling every 2 tu to T=150. Instrument =
   the check-live-mode / check-transient apertures: per-band coherent A2 over
   T=75-150 (bands 1.0-2.5 / 2.5-4.0 / 4.0-5.0 / 4.5-5.5), per-sample p50/p80,
   duty above 0.08, armed-epoch birth/death, plus Q(R,t) drift and the live
   table's own coherence.

Decision rule: the global solver earns a nonzero default only if outer
coherent A2 at T=75-150 grows monotonically with g and clears the g=0 twin
beyond the 40k noise floor, with the inner band >= 0.7x its g=0 value.
Otherwise it ships as a documented experiment at g=0 with the limiting
mechanism named, and the pre-flight already says which verdict to expect if it
fails: the outer disk's own Q, not the kernel.

## 5. Gates

- `check-poisson.js` (new): kernel vs 800x2048 dense quadrature, m=0 on
  `S0 exp(-R/Rd)` and m=2 on a synthetic `Sig2(R) cos 2phi`, same R range,
  <= 5e-3 relative (measured 1.86e-3); eps scan 0.08/0.15/0.30 reported; the
  R<0.3 inner-hole bias printed so the m=0 exclusion stays documented.
- `check-selfgrav-phase.js` (new), two scans: (A) synthetic KNOWN crest into
  `pr/pi` -> solve -> scan: well within +-10 deg of that crest (kernel/solve
  wiring: catches a double-counted +pi and an atan2 swap); (B) independent
  star-measured crest -> production kernel -> `writeTable` -> scan: well
  within +-10 deg of `arg(Phi)+pi` predicted from those phasors at every
  probe (force-path sign against OUTSIDE data). Printed, NOT gated: the real
  internal-measurement table's well vs the LOCAL crest with the kernel's
  local-input share — the solve is non-local by design (share ~0.26 at
  R=1.5 -> ~0.06 at R=4.5), so the outer well follows the dominant inner
  response's phase; that offset is the physics under study, not a bug.
- `check-gradient.js` extended: with `P.live.freeze` + the variant table,
  `accelSingle` vs central differences of `potential` to 1e-4 relative /
  1e-7 absolute (the diagnostics path already reads `o.live.amp/th`).
- `check-jacobi.js` extended: frozen variant table is a static single-pattern
  field, so p99 < 2e-3 and max < 1e-2 over 60 tu. While the table updates the
  HUD reports Jacobi n/a (finding 25's rule).
- Legacy bit-identical: `git diff --quiet -- galaxy.js` recorded in the
  worklog, plus `check-legacy.js` (new): calm-preset trajectory hash through
  the worktree `galaxy.js` equal to the same run through the 0.4.2 build
  (`git show 67ba6ea:galaxy.js`), solver = 0 / page-default parameters.
- Stability, closed loop: `liveAmpMax <= cap`; median R drift < 10% over
  150 tu; radial peak/mean <= 1.25x of the invocation's first run; min Q(t)
  >= 1.5 (no self-induced instability); no runaway epoch count.
- Perf: refresh every `refresh` substeps costs one 32x32 solve + the existing
  pipeline; the per-star cost is the unchanged live branch. Budget: global-on
  substep <= 1.2x the WKB live-on substep at N=10k (the variant's own delta
  over the shipping loop; vs live-off reported informationally), kernel
  precompute <= 100 ms — `check-perf` measures both.
- Study scripts produce their logs: `check-selfgrav-open.js` and
  `check-selfgrav-loop.js` must run clean (stability gates above); their
  verdict numbers (open-loop outer organization; ladder monotonicity vs the
  g=0 twin) go to the worklog, which records which of the three outcomes
  section 7 lists was measured.
- `smoke-page`: the select must arm the solver, set `P.live.freeze`, and the
  table must become nonzero through the UI path; `solver = 0` must reproduce
  the legacy HUD/behaviour.
- `render-png` variant `sg` (env `G=`, `EPS=`, `SOLVER=`) at settle / 75 /
  150 tu against `calm` and `live`, judged by eye (finding 20).

## 6. Page integration

- `Field`: the `live m=2 g` slider becomes `self-grav g` (still `P.live.gfb`),
  and a select `self-gravity: off | WKB (S5) | global` chooses the solver
  (`off` = the live gain fades to 0, `gfb` preserved as with the old toggle;
  selecting a solver from off with `gfb = 0` arms `gfb = 5`, same as the old
  toggle did). Key `m` toggles off / last solver. Switching solvers swaps the
  table once (freeze on for global, off for WKB, `cap` 0.10 / 0.02) and resets
  the refresh counter — a knob, not a gated transient.
- HUD names the solver and the refresh lag (`sg:global r4`); Jacobi n/a while
  the table updates, available when the loop is off (finding 25's rule; the
  frozen-table invariant is gated in check-jacobi, not on the page).
- Journal entry: what a global solve adds over the WKB term, the pre-flight
  numbers (12% of As at R=4.5 vs 0.1%), and the honest expectation.
- README: the variant and its two new check scripts.

## 7. Acceptance

Ship `selfgrav.js` + the select when every gate passes. `galaxy.js` and the
WKB path stay the default and stay byte-identical; the global solver's default
gain is whatever section 4 earned, and the worklog states which of the three
outcomes (holds the outer disk / open-loop only / unresponsive disk) was
measured.

## 8. Out of scope

- m=0 contrast solve and disk-mass redistribution (double counting + the
  R<0.3 hole) — 0.6.0.
- m=1, m=4, bar self-gravity, a second pattern speed (finding 11).
- Elliptic-integral closed forms or a finer/2D grid: quadrature is already at
  1.9e-3 and the grid resolves the m=2 wavelength with >= 7 bins.
- IC changes (a colder outer disk, sigR(R) profile). That is the lever the
  pre-flight points at if the outer disk proves unresponsive — 0.6.0.
- Any edit to `galaxy.js`.
